# Block

**Block** là một “khối cấu hình” dùng để khai báo hoặc nhóm các thiết lập liên quan đến một đối tượng nào đó.

Nói đơn giản:

> **Block = một container chứa cấu hình Terraform**
> 

Ví dụ:

```
resource "aws_s3_bucket" "logs" {
  bucket = "my-log-bucket"
}
```

Trong ví dụ trên:

```
resource "aws_s3_bucket" "logs" {
  ...
}
```

là một **block**.

## Cấu trúc của một block

Một block thường có dạng:

```
block_type "label_1" "label_2" {
  argument_name = expression

  nested_block {
    argument_name = expression
  }
}
```

Ví dụ:

```
resource "aws_instance" "web" {
  ami           = "ami-123456"
  instance_type = "t2.micro"

  tags = {
    Name = "web-server"
  }
}
```

Ở đây:

| Thành phần | Ý nghĩa |
| --- | --- |
| `resource` | Loại block |
| `"aws_instance"` | Label thứ nhất, chỉ loại resource của provider AWS |
| `"web"` | Label thứ hai, tên nội bộ trong Terraform |
| `{ ... }` | Phần thân của block |
| `ami`, `instance_type`, `tags` | Các argument bên trong block |

## Top level block types

### `terraform`

Used to configure Terraform itself, including:

- `required_version`
- `required_providers`
- `backend`
- HCP Terraform integration settings

Cấu hình chính bản thân Terraform, bao gồm:

- `required_version`: phiên bản Terraform bắt buộc hoặc được phép sử dụng
- `required_providers`: các provider cần thiết và phiên bản của chúng
- `backend`: nơi lưu trữ Terraform state
- Cài đặt tích hợp với HCP Terraform

```hcl
terraform {
  required_version = ">= 1.5.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }

  backend "s3" {
    bucket = "my-tf-state"
    key    = "network/terraform.tfstate"
    region = "us-east-1"
  }
}
```

This is the control block for versioning, provider installation requirements, and backend configuration.

Đây là **block điều khiển** dùng để cấu hình:

- Phiên bản Terraform
- Yêu cầu cài đặt provider
- Cấu hình backend để lưu trữ state

### `provider`

Configures a provider plugin.

```hcl
provider "aws" {
  region = "us-east-1"
}
```

Providers may also use aliases for multiple configurations.

Các provider cũng có thể sử dụng **alias** để tạo nhiều cấu hình khác nhau.

```hcl
provider "aws" {
  alias  = "east"
  region = "us-east-1"
}
```

### `resource`

Trong Terraform, **`resource` block** dùng để **khai báo một tài nguyên hạ tầng mà Terraform sẽ quản lý**.

Một **resource block** bao gồm:

- Loại resource
- Tên cục bộ
- Các argument riêng của provider
- Các meta-argument tùy chọn
- `lifecycle` tùy chọn
- `connection` tùy chọn
- `provisioner` tùy chọn

Cú pháp cơ bản:

```hcl
resource "<resource_type>" "<local_name>" {
  argument_name = expression
}
```

Ví dụ:

```hcl
resource "aws_instance" "web" {
  # provider-specific arguments
  ami           = "ami-..."
  instance_type = "t2.micro"

  # meta-arguments
  count = 1

  # lifecycle block
  lifecycle {
    prevent_destroy = true
  }

  # provisioner nếu cần, nhưng thường không khuyến khích lạm dụng
}
```

Tài liệu tham chiếu về **resource block** của Terraform cũng ghi nhận rằng Terraform hỗ trợ `terraform_data` được tích hợp sẵn. `terraform_data` dùng để lưu trữ giá trị và kích hoạt các thao tác Terraform mà không tạo ra hạ tầng thật.

### `data`

Declares a read only lookup.

`data` block dùng để **đọc thông tin từ bên ngoài Terraform** hoặc từ provider, nhưng **không tạo, không sửa, không xoá infrastructure**. Nói cách khác, nó chỉ “query/read” dữ liệu để dùng trong cấu hình Terraform. HashiCorp mô tả `data` block là cách lấy dữ liệu về một resource từ provider mà không provision infrastructure object tương ứng. 

Ví dụ cú pháp:

```hcl
data "<DATA_SOURCE_TYPE>" "<LOCAL_NAME>" {
  # arguments để lọc / tìm dữ liệu
}
```

Ví dụ với AWS AMI:

```hcl
data "aws_ami" "ubuntu" {
  most_recent = true

  owners = ["099720109477"] # Canonical

  filter {
    name   = "name"
    values = ["ubuntu/images/hvm-ssd/ubuntu-jammy-22.04-amd64-server-*"]
  }
}
```

Sau đó dùng kết quả:

```hcl
resource "aws_instance" "web" {
  ami           = data.aws_ami.ubuntu.id
  instance_type = "t3.micro"
}
```

Cách reference chung là:

```hcl
data.<TYPE>.<LOCAL_NAME>.<ATTRIBUTE>
```

Ví dụ:

```hcl
data.aws_ami.ubuntu.id
```

### `terraform_data`

`terraform_data` trong Terraform là **một resource đặc biệt được Terraform tích hợp sẵn**, dùng để lưu giá trị vào state hoặc tạo trigger thay đổi, nhưng **không tạo ra hạ tầng thật** như EC2, S3, VPC. 

Điểm quan trọng: `terraform_data` là **resource block**, không phải `data block`.

#### `terraform_data` dùng để làm gì?

Theo tài liệu Terraform, `terraform_data` có lifecycle chuẩn như một resource bình thường, nhưng bản thân nó không thao tác với hệ thống bên ngoài. Nó luôn có sẵn thông qua provider built-in `terraform.io/builtin/terraform`, nên không cần khai báo provider riêng.

Nó thường dùng để:

1. Lưu một giá trị vào Terraform state.
2. Làm trigger để thay thế resource khác.
3. Chạy `provisioner` khi không có resource thật phù hợp để gắn provisioner.
4. Thay thế cho `null_resource` trong nhiều workflow mới. Terraform 1.4 giới thiệu `terraform_data` như một managed resource built-in thay cho `null_resource`.

#### Cấu trúc cơ bản

```
resource "terraform_data" "example" {
  input = {
    name = "app"
    env  = "dev"
  }
}
```

Sau khi `terraform apply`, Terraform sẽ lưu giá trị `input` này vào state và xuất ra thông qua thuộc tính `output`.

Ví dụ dùng output:

```
output "data_value" {
  value = terraform_data.example.output
}
```

#### Hai argument chính

- `input`
    
    Dùng để lưu một giá trị vào state.
    
    ```
    resource "terraform_data" "app_info" {
      input = {
        app_name = "my-app"
        version  = "1.0.0"
      }
    }
    ```
    
    Có thể lấy lại bằng:
    
    ```
    terraform_data.app_info.output
    ```
    
    Terraform docs mô tả `input` là giá trị được lưu trong state, và `output` là giá trị được tính từ `input`.
    
- `triggers_replace`
    
    Dùng để nói với Terraform rằng: **khi giá trị này thay đổi thì hãy replace `terraform_data` resource này**.
    
    ```
    resource "terraform_data" "deploy_trigger" {
      triggers_replace = [
        var.image_tag
      ]
    }
    ```
    
    Nếu `var.image_tag` đổi từ `"v1"` sang `"v2"`, Terraform sẽ destroy và create lại `terraform_data.deploy_trigger`.
    

#### Ví dụ thực tế: trigger deploy khi image tag thay đổi

```hcl
variable "image_tag" {
  type = string
}

resource "terraform_data" "deploy" {
  triggers_replace = [
    var.image_tag
  ]

  provisioner "local-exec" {
    command = "echo Deploying image tag ${var.image_tag}"
  }
}
```

Khi `image_tag` thay đổi, Terraform sẽ replace `terraform_data.deploy`, từ đó chạy lại `local-exec`.

#### Dùng với `replace_triggered_by`

Một use case hay là dùng `terraform_data` để ép resource khác bị replace khi một giá trị thường như variable/local thay đổi.

Ví dụ:

```
variable "revision" {
  type = string
}

resource "terraform_data" "revision" {
  input = var.revision
}

resource "aws_instance" "web" {
  ami           = "ami-123456"
  instance_type = "t3.micro"

  lifecycle {
    replace_triggered_by = [
      terraform_data.revision
    ]
  }
}
```

Ở đây, nếu `var.revision` thay đổi, `terraform_data.revision` thay đổi, từ đó `aws_instance.web` cũng bị replace.

Lý do cần cách này: `replace_triggered_by` yêu cầu tham chiếu đến resource address, không dùng trực tiếp plain value như variable hoặc local. Terraform docs khuyến nghị dùng `terraform_data` để gián tiếp đưa plain value vào cơ chế replace này.

#### Khác gì với `data block`?

Rất dễ nhầm:

```
data "aws_ami" "ubuntu" {
  most_recent = true
}
```

`data block` dùng để **đọc thông tin từ bên ngoài**, ví dụ đọc AMI, VPC, subnet, hosted zone. Data source chỉ đọc, không quản lý lifecycle của object bên ngoài.

Còn:

```
resource "terraform_data" "example" {
  input = "abc"
}
```

`terraform_data` là **resource**, có lifecycle `create`, `update`, `replace`, `destroy`, nhưng nó chỉ tồn tại trong Terraform state, không tạo hạ tầng thật.

#### So sánh nhanh với `null_resource`

Trước đây hay dùng:

```
resource "null_resource" "deploy" {
  triggers = {
    image_tag = var.image_tag
  }

  provisioner "local-exec" {
    command = "echo deploy"
  }
}
```

Hiện nay có thể dùng:

```
resource "terraform_data" "deploy" {
  triggers_replace = [
    var.image_tag
  ]

  provisioner "local-exec" {
    command = "echo deploy"
  }
}
```

`terraform_data` tốt hơn trong nhiều trường hợp vì là resource built-in của Terraform, không cần cài thêm `null` provider.

#### Tóm lại

`terraform_data` là một **resource giả lập / utility resource** của Terraform. Nó không tạo infrastructure thật, nhưng có lifecycle như resource thật. Nó thường dùng để lưu giá trị trong state, tạo trigger thay đổi, ép replace resource khác, hoặc chạy provisioner trong một số workflow đặc biệt.

Cách nhớ đơn giản:

> `data` block = đọc dữ liệu từ bên ngoài.
> 
> 
> `terraform_data` resource = lưu dữ liệu/triggers vào Terraform state để điều khiển lifecycle.
> 

### `variable`

Declares an input variable for a module.

```hcl
variable "region" {
  type        = string
  description = "AWS region"
  default     = "us-east-1"
}
```

Variables make modules customizable without editing source code.

### `locals`

Defines local values computed from expressions.

`locals` block trong Terraform dùng để **định nghĩa các giá trị nội bộ trong một module**, giúp tái sử dụng biểu thức nhiều lần mà không phải viết lặp lại.

Theo Terraform, `locals` cho phép gán tên cho một expression, sau đó dùng lại bằng cú pháp `local.<tên_local>` trong cùng module.

```hcl
locals {
  project_name = "my-app"
  environment  = "dev"

  common_tags = {
    Project     = local.project_name
    Environment = local.environment
    ManagedBy   = "Terraform"
  }
}

resource "aws_s3_bucket" "example" {
  bucket = "${local.project_name}-${local.environment}-bucket"

  tags = local.common_tags
}
```

Locals are referenced as `local.name`. Multiple `locals` blocks are merged within a module.

#### Khác nhau giữa `variable` và `locals`

| Thành phần | Ý nghĩa |
| --- | --- |
| `variable` | Giá trị đầu vào, người dùng có thể truyền từ ngoài vào |
| `locals` | Giá trị nội bộ, được tính bên trong Terraform module |
| `var.name` | Dùng để gọi input variable |
| `local.name` | Dùng để gọi local value |

### `output`

Exposes values from a module.

```hcl
output "instance_id" {
  value = aws_instance.web.id
}
```

Outputs are used on the CLI, in HCP Terraform, and by other configurations or parent modules.

Terraform only prints root module outputs after apply, not child-module outputs directly

### `module`

`module` block dùng để **gọi một module khác** vào cấu hình Terraform hiện tại. Module đó có thể là:

- module local trong project của bạn
- module từ Terraform Registry
- module từ Git repository
- module từ storage/archive remote

```hcl
module "network" {
  source = "./modules/network"
  cidr   = "10.0.0.0/16"
}
```

### `check`

Validates infrastructure outside the normal resource lifecycle. Terraform runs check blocks as the last step of `plan` or `apply`.

```hcl
check "service_health" {
  assert {
    condition     = data.http.example.status_code == 200
    error_message = "Service is not healthy."
  }
}
```

### `import`

Use `import` blocks to adopt existing infrastructure into Terraform management. This is the preferred configuration driven approach compared with older ad hoc import only workflows.

Dùng `import` blocks để đưa hạ tầng đã tồn tại vào Terraform quản lý. Đây là cách tiếp cận được khuyến nghị hơn vì nó dựa trên cấu hình, thay vì kiểu import thủ công, rời rạc bằng lệnh `terraform import` như trước đây.

```hcl
import {
  id = "i-0123456789abcdef0"
  to = aws_instance.web
}
```

Terraform can also generate configuration during plan with `generate-config-out` in certain workflows.

Terraform cũng có thể tạo ra cấu hình trong quá trình `plan` bằng tùy chọn `generate-config-out` trong một số workflow nhất định.

[Import](Block/Import%2037132dbb34d080fb834fe49aad46de09.md)

### `moved`

Use `moved` blocks to preserve object identity in state when renaming or restructuring addresses. This is critical during refactoring and module extraction.

Dùng `moved` blocks để giữ nguyên danh tính của object trong Terraform state khi bạn đổi tên resource, đổi địa chỉ resource, hoặc tái cấu trúc module. Điều này rất quan trọng khi refactor Terraform code hoặc tách resource ra thành module riêng.

```hcl
moved {
  from = aws_instance.old_name
  to   = aws_instance.new_name
}
```

## Block khác gì argument?

**Argument** là dòng gán giá trị:

```
bucket = "my-example-bucket"
```

Còn **block** là khối chứa nhiều cấu hình:

```
resource "aws_s3_bucket" "example" {
  bucket = "my-example-bucket"
}
```

Tóm gọn:

```
resource "aws_s3_bucket" "example" { # block
  bucket = "my-example-bucket"       # argument
}
```

## Kết luận

Trong Terraform, **block là đơn vị cấu trúc chính của file cấu hình**. Nó dùng để khai báo provider, resource, variable, output, module, backend, lifecycle, dynamic block và nhiều thành phần khác.

Có thể hiểu đơn giản:

> **Block cho Terraform biết bạn đang khai báo cái gì.
Argument bên trong block cho Terraform biết cấu hình chi tiết của cái đó.**
>
