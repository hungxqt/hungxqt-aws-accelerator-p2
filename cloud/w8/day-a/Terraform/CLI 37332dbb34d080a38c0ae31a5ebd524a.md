# CLI

**Terraform CLI** là công cụ dòng lệnh `terraform` dùng để làm việc với Terraform: khởi tạo project, tải provider/module, kiểm tra cấu hình, tạo execution plan, apply hạ tầng, destroy hạ tầng, quản lý state, import resource, quản lý workspace, test module và chạy Terraform trong CI/CD. HashiCorp phân biệt rõ Terraform CLI với các thành phần khác như **HCP Terraform** và **Terraform providers**, vì provider được phát triển và phát hành độc lập với Terraform CLI.

Cú pháp tổng quát:

```
terraform [global options] <subcommand> [args]
```

Ví dụ:

```
terraform init
terraform plan
terraform apply
terraform destroy
```

## 2. Vai trò của CLI trong Terraform workflow

Terraform là công cụ **Infrastructure as Code** theo mô hình declarative. Bạn viết trạng thái mong muốn trong file `.tf`, còn Terraform CLI là thứ thực thi các bước để biến trạng thái mong muốn đó thành hạ tầng thật.

Một workflow cơ bản thường là:

```
terraform init
terraform fmt
terraform validate
terraform plan
terraform apply
terraform output
```

Nếu muốn xóa hạ tầng:

```
terraform destroy
```

Các lệnh chính được Terraform CLI liệt kê gồm `init`, `validate`, `plan`, `apply`, `destroy`; ngoài ra còn có nhiều lệnh phụ như `fmt`, `state`, `import`, `output`, `show`, `workspace`, `providers`, `console`, `graph`, `test`, `login`, `logout`, `force-unlock`.

## 3. Các nhóm lệnh quan trọng

### Nhóm lifecycle chính

| Lệnh | Ý nghĩa |
| --- | --- |
| `terraform init` | Khởi tạo working directory, tải provider, module, cấu hình backend |
| `terraform fmt` | Format code Terraform theo chuẩn |
| `terraform validate` | Kiểm tra cú pháp và tính nhất quán nội bộ của cấu hình |
| `terraform plan` | Xem trước Terraform sẽ tạo, sửa, xóa gì |
| `terraform apply` | Thực thi plan để thay đổi hạ tầng thật |
| `terraform destroy` | Xóa toàn bộ resource Terraform đang quản lý trong workspace hiện tại |

`terraform init` là lệnh đầu tiên nên chạy sau khi tạo mới hoặc clone một Terraform configuration. Lệnh này an toàn để chạy nhiều lần và dùng để đưa thư mục làm việc về trạng thái sẵn sàng cho các lệnh khác.

`terraform validate` chỉ kiểm tra cấu hình Terraform có hợp lệ về cú pháp, attribute, type và tính nhất quán nội bộ hay không; nó không kiểm tra remote service, remote state hoặc provider API. Vì vậy, muốn kiểm tra theo context thật của workspace, biến đầu vào và state hiện tại thì dùng `terraform plan`.

`terraform plan` tạo execution plan để xem trước thay đổi. Khi plan, Terraform đọc state hiện tại, refresh thông tin remote object, so sánh configuration với state trước đó, sau đó đề xuất các action cần làm để hạ tầng thật khớp với code. Lệnh này **không tự thay đổi hạ tầng thật**.

`terraform apply` thực thi các operation được đề xuất trong plan. Nếu chạy `terraform apply` trực tiếp, Terraform tự tạo plan rồi hỏi xác nhận; nếu truyền vào saved plan file, Terraform apply đúng plan đó mà không hỏi xác nhận thêm. Đây là workflow hay dùng trong CI/CD.

`terraform destroy` xóa các object đang được Terraform quản lý. Lệnh này hữu ích với môi trường tạm như dev, test, sandbox, nhưng rất nguy hiểm với môi trường production nếu không có kiểm soát.

## 4. `terraform init` — lệnh khởi tạo quan trọng nhất

Chạy:

```
terraform init
```

Lệnh này thường làm các việc sau:

```
- Kiểm tra cấu hình Terraform trong thư mục hiện tại
- Khởi tạo backend nếu có cấu hình backend
- Tải provider cần thiết
- Tải module từ Terraform Registry, Git, local path, v.v.
- Tạo/thay đổi thư mục .terraform/
- Tạo/cập nhật file .terraform.lock.hcl
```

Một số option hay dùng:

```
terraform init -upgrade
```

Dùng khi muốn nâng version provider/module theo constraint hiện tại.

```
terraform init -backend=false
```

Dùng trong CI hoặc khi chỉ muốn validate module mà không kết nối backend.

```
terraform init -reconfigure
```

Dùng khi backend config thay đổi và bạn muốn cấu hình lại backend.

```
terraform init -migrate-state
```

Dùng khi đổi backend và muốn migrate state sang backend mới.

Sau khi cài provider thành công, Terraform ghi thông tin provider được chọn vào `.terraform.lock.hcl`; HashiCorp khuyến nghị commit file lock này vào version control để những lần `init` sau chọn đúng version provider như trước.

## 5. `.terraform/` và `.terraform.lock.hcl`

Terraform CLI thường tạo ra:

```
.terraform/
.terraform.lock.hcl
```

`.terraform/` là thư mục local cache, chứa provider, module đã tải, metadata backend. Thư mục này **không nên commit lên Git**.

`.terraform.lock.hcl` là dependency lock file. Terraform dùng file này để ghi nhớ version provider đã chọn và checksum của provider package. File này nên được commit để team dùng cùng một version provider, tránh việc mỗi máy hoặc mỗi pipeline tự chọn version khác nhau.

Ví dụ `.gitignore` thường dùng:

```
.terraform/
*.tfstate
*.tfstate.*
crash.log
crash.*.log
*.tfvars
*.tfvars.json
override.tf
override.tf.json
*_override.tf
*_override.tf.json
.terraform.tfstate.lock.info
```

Lưu ý: không nên bỏ qua `.terraform.lock.hcl`.

## 6. `terraform fmt`

Lệnh này format code Terraform theo style chuẩn:

```
terraform fmt
```

Format đệ quy toàn bộ thư mục con:

```
terraform fmt -recursive
```

Kiểm tra format trong CI, không sửa file:

```
terraform fmt -check-recursive
```

Hiển thị diff:

```
terraform fmt -diff
```

Trong CI/CD, nên chạy:

```
terraform fmt -check-recursive
terraform validate
```

## 7. `terraform validate`

Chạy:

```
terraform validate
```

Nếu trong CI chỉ muốn validate mà không kết nối backend thật:

```
terraform init-backend=false
terraform validate
```

`validate` phù hợp để kiểm tra module reusable vì nó kiểm tra lỗi cú pháp, tên attribute, kiểu dữ liệu và internal consistency. Tuy nhiên, nó không đảm bảo resource có tạo được trên AWS/Azure/GCP hay không, vì chuyện đó phụ thuộc provider API, IAM permission, quota, region, backend, state và biến runtime.

## 8. `terraform plan`

Chạy cơ bản:

```
terraform plan
```

Chỉ định biến:

```
terraform plan -var="environment=dev"
terraform plan -var-file="dev.tfvars"
```

Lưu plan ra file:

```
terraform plan -out=tfplan
```

Xem plan đã lưu:

```
terraform show tfplan
```

Xuất JSON để tool khác đọc:

```
terraform show -json tfplan > plan.json
```

Một số option quan trọng:

```
terraform plan -destroy
```

Tạo plan để destroy toàn bộ resource đang quản lý.

```
terraform plan -refresh-only
```

Chỉ kiểm tra drift và cập nhật state/output theo hạ tầng thật, không thay đổi resource thật.

```
terraform plan -target=aws_instance.example
```

Chỉ target một phần dependency graph. Không nên lạm dụng, chủ yếu dùng khi xử lý sự cố.

```
terraform plan -replace=aws_instance.example
```

Yêu cầu Terraform thay resource cụ thể thay vì update tại chỗ.

```
terraform plan -detailed-exitcode
```

Rất hữu ích trong CI:

```
0 = không có thay đổi
1 = lỗi
2 = có thay đổi
```

## 9. `terraform apply`

Chạy cơ bản:

```
terraform apply
```

Terraform sẽ tạo plan, hiển thị thay đổi, sau đó yêu cầu nhập:

```
yes
```

Apply không hỏi xác nhận:

```
terraform apply -auto-approve
```

Cẩn thận với `-auto-approve`, đặc biệt trong môi trường production. HashiCorp khuyến nghị chỉ dùng khi bạn kiểm soát được việc không ai thay đổi hạ tầng ngoài Terraform workflow, nhằm giảm rủi ro drift hoặc thay đổi ngoài dự kiến.

Workflow an toàn hơn:

```
terraform plan -out=tfplan
terraform show tfplan
terraform apply tfplan
```

Khi apply saved plan, Terraform thực thi đúng plan đã lưu và không hỏi xác nhận thêm; HashiCorp cũng lưu ý không thể truyền thêm planning options khi apply saved plan vì quyết định hành động đã nằm trong plan file.

## 10. `terraform destroy`

Chạy:

```
terraform destroy
```

Hoặc tạo plan destroy trước:

```
terraform plan -destroy-out=destroy.tfplan
terraform apply destroy.tfplan
```

Không hỏi xác nhận:

```
terraform destroy -auto-approve
```

Trong production, nên tránh destroy trực tiếp. Nên dùng plan file, approval thủ công, branch protection, environment protection và kiểm soát IAM.

## 11. `terraform output`

Dùng để xem output của root module:

```
terraform output
```

Xem một output cụ thể:

```
terraform output vpc_id
```

Xuất JSON:

```
terraform output-json
```

Lấy raw string, hữu ích trong script:

```
terraform output-raw alb_dns_name
```

Ví dụ:

```
output "vpc_id" {
  value = aws_vpc.main.id
}
```

Sau khi apply:

```
terraform output vpc_id
```

## 12. `terraform show`

Dùng để xem state hoặc plan file:

```
terraform show
terraform show tfplan
terraform show-json tfplan
```

Khác biệt:

```
terraform output = chỉ xem output values
terraform show   = xem state hoặc saved plan chi tiết hơn
```

## 13. Quản lý state bằng Terraform CLI

Terraform state là dữ liệu Terraform dùng để map resource trong code với object thật ngoài cloud. Terraform dùng state để biết object nào đang được quản lý và cần thay đổi gì.

Các lệnh state quan trọng:

```
terraform state list
terraform state show <address>
terraform statemv <source> <destination>
terraform staterm <address>
terraform state pull
terraform state push
terraform state replace-provider
```

Ví dụ:

```
terraform state list
```

Liệt kê resource trong state.

```
terraform state show aws_instance.web
```

Xem thông tin một resource trong state.

```
terraform statemv aws_instance.old aws_instance.new
```

Đổi địa chỉ resource trong state, thường dùng khi refactor code mà không muốn recreate resource.

```
terraform staterm aws_s3_bucket.example
```

Gỡ resource khỏi state nhưng **không xóa resource thật**.

```
terraform state pull > state.json
```

Tải state hiện tại ra stdout/file.

`terraform state` là nhóm lệnh nâng cao để sửa state thay vì sửa trực tiếp file state. HashiCorp lưu ý các state subcommands có thể làm việc với remote state giống như local state, nhưng mỗi lần đọc/ghi sẽ cần round trip qua network.

State file có thể chứa thông tin nhạy cảm. HashiCorp khuyến nghị xem state là sensitive data, không đưa state local vào Git, và nên dùng remote backend có kiểm soát truy cập/mã hóa phù hợp.

## 14. `terraform import`

Dùng để đưa resource đã tồn tại ngoài cloud vào Terraform state.

Cú pháp:

```
terraform import ADDRESS ID
```

Ví dụ import S3 bucket:

```
terraform import aws_s3_bucket.logs my-existing-bucket
```

Import chỉ liên kết object thật với state tại địa chỉ resource tương ứng. Bạn vẫn cần viết block resource trong `.tf` sao cho khớp với resource thật, nếu không lần `plan` tiếp theo có thể báo diff. Theo docs, `terraform import` tìm resource hiện có bằng `ID` và import vào Terraform state tại `ADDRESS`; address có thể nằm ở root module hoặc child module.

Ví dụ import vào module:

```
terraform import'module.vpc.aws_vpc.this[0]' vpc-0123456789abcdef0
```

## 15. `terraform workspace`

Workspace là cơ chế để có nhiều state khác nhau cho cùng một configuration.

Các lệnh:

```
terraform workspace list
terraform workspace show
terraform workspace new dev
terraform workspace select dev
terraform workspace select-or-create staging
terraform workspace delete dev
```

Ví dụ:

```
terraform workspace new dev
terraform workspace select dev
terraform apply -var-file=dev.tfvars
```

`terraform workspace` là command group để quản lý workspace; `workspace select` chọn workspace khác cho các thao tác Terraform tiếp theo, và option `-or-create` có thể tạo workspace nếu chưa tồn tại.

Lưu ý thực chiến: workspace phù hợp cho môi trường đơn giản hoặc cùng một backend tách state theo tên workspace. Với production nghiêm túc, nhiều team thích tách hẳn thư mục/backend/account theo môi trường, ví dụ:

```
environments/
  dev/
  staging/
  prod/
```

## 16. `terraform providers`

Dùng để xem và quản lý provider dependency.

```
terraform providers
terraform providers schema-json
terraform providers lock
terraform providers mirror ./plugins
```

`terraform providers lock` có thể thêm provider selection information vào dependency lock file mà không cần initialize provider. Lệnh này hữu ích khi team chạy Terraform trên nhiều platform như Windows, Linux, macOS và muốn pre-populate checksum cho các platform đó.

Ví dụ lock cho nhiều platform:

```
terraform providers lock \
-platform=linux_amd64 \
-platform=windows_amd64 \
-platform=darwin_arm64
```

## 17. `terraform get`

Dùng để tải hoặc cập nhật module remote:

```
terraformget
terraformget-update
```

Thực tế, `terraform init` thường đã tải module rồi, nên bạn ít cần dùng `terraform get` riêng.

## 18. `terraform graph`

Tạo dependency graph dạng DOT:

```
terraform graph > graph.dot
```

Có thể convert sang ảnh nếu có Graphviz:

```
dot -Tpng graph.dot -o graph.png
```

Lệnh này hữu ích để hiểu dependency giữa resource, đặc biệt khi debug vì sao Terraform tạo resource theo thứ tự nhất định.

## 19. `terraform console`

Mở interactive console để test expression Terraform:

```
terraform console
```

Ví dụ trong console:

```
> upper("dev")
"DEV"

> cidrsubnet("10.0.0.0/16", 8, 1)
"10.0.1.0/24"
```

Lệnh này rất hữu ích khi học function, expression, `for`, `for_each`, `merge`, `lookup`, `try`, `can`, `cidrsubnet`.

## 20. `terraform refresh` và `refresh-only`

Lệnh cũ:

```
terraform refresh
```

Nhưng lệnh này đã deprecated. HashiCorp khuyến nghị dùng:

```
terraform plan -refresh-only
terraform apply -refresh-only
```

`terraform refresh` đọc remote object và cập nhật state, nhưng vì nó có thể tự động thay state theo thông tin đọc được từ provider nên không an toàn bằng `plan/apply -refresh-only`, nơi bạn có cơ hội review thay đổi trước.

## 21. `terraform force-unlock`

Khi Terraform đang dùng backend có state locking, nếu một run bị chết giữa chừng có thể để lại lock.

Ví dụ lỗi:

```
Error acquiring the state lock
```

Mở lock:

```
terraform force-unlock <LOCK_ID>
```

Chỉ dùng khi chắc chắn không còn process Terraform nào đang chạy. Nếu unlock nhầm trong khi người khác đang apply, state có thể bị conflict hoặc corrupt.

## 22. `terraform taint` và `terraform untaint`

`taint` đánh dấu resource là không còn healthy để lần apply sau Terraform replace nó:

```
terraform taint aws_instance.web
terraform apply
```

Bỏ taint:

```
terraform untaint aws_instance.web
```

Tuy nhiên, workflow hiện đại thường nên dùng:

```
terraform apply-replace=aws_instance.web
```

hoặc:

```
terraform plan -replace=aws_instance.web -out=tfplan
terraform apply tfplan
```

Cách này rõ ràng hơn vì replacement nằm trong plan.

## 23. `terraform login` và `terraform logout`

Dùng khi làm việc với HCP Terraform hoặc Terraform Enterprise:

```
terraform login
terraform logout
```

`login` lưu credential token local để Terraform CLI có thể giao tiếp với remote host.

## 24. `terraform test`

Dùng để test Terraform module/root module bằng file test.

```
terraform test
```

Chạy một test file cụ thể:

```
terraform test -filter=tests/vpc.tftest.hcl
```

Xuất JSON:

```
terraform test -json
```

HashiCorp mô tả `terraform test` là lệnh load và execute Terraform testing files; nó có thể chạy plan hoặc apply theo test spec. Cần cẩn thận vì `terraform test` có thể tạo hạ tầng thật và phát sinh chi phí.

## 25. Terraform Stacks CLI

Ở các phiên bản mới, Terraform CLI có nhóm lệnh `terraform stacks` để quản lý Terraform Stacks, đặc biệt trong HCP Terraform/Terraform Enterprise. Nhóm này dùng để initialize stack configuration, validate stack definitions, tạo/quản lý stacks và xử lý deployment operations.

Ví dụ:

```
terraform stacks version
terraform stacks init
terraform stacks validate
terraform stacks create
terraform stacks list
terraform stacks deployment-run list
terraform stacks deployment-run approve
terraform stacks deployment-run cancel
```

Với Terraform Enterprise, docs yêu cầu cấu hình `TF_STACKS_HOSTNAME` trỏ đến hostname của Terraform Enterprise instance.

## 26. Global options

Một số global option dùng trước subcommand:

```
terraform -help
terraform -version
terraform -chdir=environments/prod plan
terraform -chdir=environments/prod apply
```

- `chdir=DIR` cho phép Terraform chuyển sang thư mục khác trước khi chạy subcommand. Đây là cách hiện đại để chạy Terraform từ root repo nhưng target vào thư mục environment cụ thể.
    
    Ví dụ:
    
    ```
    terraform-chdir=environments/development init
    terraform-chdir=environments/development plan
    terraform-chdir=environments/development apply
    ```
    

Bật shell autocomplete:

```
terraform -install-autocomplete
```

Tắt autocomplete:

```
terraform -uninstall-autocomplete
```

Terraform hỗ trợ tab-completion cho bash hoặc zsh thông qua lệnh cài autocomplete.

## 27. Environment variables quan trọng

Terraform CLI có nhiều biến môi trường để tùy chỉnh hành vi CLI. Không biến nào bắt buộc trong mọi trường hợp, nhưng chúng rất hữu ích cho debug, CI/CD và truyền biến đầu vào.

| Biến | Ý nghĩa |
| --- | --- |
| `TF_LOG` | Bật log debug, ví dụ `TRACE`, `DEBUG`, `INFO` |
| `TF_LOG_PATH` | Ghi log ra file |
| `TF_VAR_name` | Truyền giá trị cho input variable `name` |
| `TF_CLI_ARGS` | Thêm default arguments cho mọi lệnh |
| `TF_CLI_ARGS_plan` | Thêm default arguments riêng cho lệnh `plan` |
| `TF_INPUT` | Bật/tắt prompt input |
| `TF_DATA_DIR` | Đổi nơi Terraform lưu data thay vì `.terraform/` |
| `TF_WORKSPACE` | Chọn workspace qua environment variable |
| `TF_IN_AUTOMATION` | Báo cho Terraform biết đang chạy trong automation |
| `TF_PLUGIN_CACHE_DIR` | Cache provider plugin |

Ví dụ debug:

```
exportTF_LOG=TRACE
terraform plan
```

Ghi log ra file:

```
exportTF_LOG=DEBUG
exportTF_LOG_PATH=terraform.log
terraform apply
```

Truyền biến:

```
exportTF_VAR_region=ap-southeast-1
exportTF_VAR_environment=dev
terraform plan
```

Tắt prompt trong CI:

```
exportTF_INPUT=false
terraform plan
```

Thêm default args cho plan:

```
exportTF_CLI_ARGS_plan="-input=false -no-color"
terraform plan
```

HashiCorp ghi rõ `TF_VAR_name` được dùng để set input variables, còn `TF_CLI_ARGS`/`TF_CLI_ARGS_name` cho phép chèn arguments vào sau subcommand và trước flags được truyền trực tiếp trên command line; flags gõ trực tiếp sẽ có precedence cao hơn.

## 30. Workflow CI/CD chuẩn

Một pipeline Terraform thường chia thành 2 phase:

```
Pull Request:
- terraform fmt -check
- terraform init -backend=false hoặc init backend read-only tùy workflow
- terraform validate
- terraform plan
- comment plan lên PR

Merge/main branch:
- terraform init
- terraform plan -out=tfplan
- manual approval
- terraform apply tfplan
```

Ví dụ GitHub Actions logic:

```
terraform init
terraform fmt-check-recursive
terraform validate
terraform plan-no-color-out=tfplan
terraform show-no-color tfplan
```

Apply:

```
terraform apply-auto-approve tfplan
```

Trong automation, saved plan mode là lựa chọn phổ biến vì plan được tạo ở một bước, review/approve ở bước khác, rồi apply đúng plan đó. Docs của `terraform apply` cũng nêu saved plan mode phù hợp khi chạy Terraform trong automation.

## 32. Terraform CLI khác gì với Provider, Backend, Module?

| Thành phần | Vai trò |
| --- | --- |
| Terraform CLI | Tool dòng lệnh chạy `init`, `plan`, `apply`, `state`, v.v. |
| Provider | Plugin giao tiếp với API của AWS, Azure, GCP, Kubernetes, GitHub, v.v. |
| Backend | Nơi lưu state, ví dụ local, S3, HCP Terraform |
| Module | Gói Terraform code có thể tái sử dụng |
| State | File/dữ liệu ghi mapping giữa code và resource thật |
| Lock file | Ghi version/checksum provider đã chọn |

Ví dụ:

```
terraform {
  backend "s3" {
    bucket = "my-terraform-state"
    key    = "dev/vpc.tfstate"
    region = "ap-southeast-1"
  }

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
}
```

Khi chạy:

```
terraform init
```

CLI sẽ đọc block `terraform`, cấu hình backend S3, tải AWS provider, và cập nhật `.terraform.lock.hcl`.

## 33. Lỗi thường gặp với Terraform CLI

### Chưa chạy `init`

```
Error: Inconsistent dependency lock file
Error: Required plugins are not installed
```

Cách xử lý:

```
terraform init
```

### Backend thay đổi

```
Backend configuration changed
```

Cách xử lý tùy tình huống:

```
terraform init-reconfigure
```

hoặc:

```
terraform init-migrate-state
```

### Provider version conflict

```
Failed to query available provider packages
```

Cách xử lý:

```
terraform init-upgrade
```

Hoặc sửa constraint:

```
version = "~> 6.0"
```

### State lock

```
Error acquiring the state lock
```

Cách xử lý nếu chắc chắn lock bị kẹt:

```
terraform force-unlock <LOCK_ID>
```

### Drift

Hạ tầng bị sửa ngoài Terraform. Kiểm tra:

```
terraform plan
```

Chỉ sync state sau khi review:

```
terraform plan -refresh-only
terraform apply -refresh-only
```

### Resource đã tồn tại

```
AlreadyExists
BucketAlreadyExists
EntityAlreadyExists
```

Cách xử lý thường là import:

```
terraform import aws_s3_bucket.logs my-existing-bucket
```

Sau đó chỉnh code cho khớp.

## 36. Câu trả lời phỏng vấn mẫu

**Hỏi: Terraform CLI là gì?**

Terraform CLI là command-line tool `terraform` dùng để vận hành toàn bộ lifecycle của Terraform configuration: init project, tải provider/module, validate code, tạo execution plan, apply thay đổi lên hạ tầng thật, destroy resource, quản lý state, import resource có sẵn và tích hợp vào CI/CD. Nó khác với provider vì provider là plugin giao tiếp với API của cloud/service, còn CLI là công cụ điều phối workflow Terraform.

**Hỏi: `terraform plan` khác gì `terraform apply`?**

`terraform plan` chỉ tạo execution plan để xem Terraform định tạo, sửa, xóa gì; nó không thay đổi hạ tầng thật. `terraform apply` thực thi các operation trong plan để thay đổi hạ tầng thật. Trong môi trường production, nên tạo saved plan bằng `terraform plan -out=tfplan`, review plan, sau đó `terraform apply tfplan`.

**Hỏi: Vì sao cần `terraform init`?**

Vì `init` chuẩn bị working directory cho Terraform: cấu hình backend, tải provider, tải module và tạo/cập nhật lock file. Đây là lệnh đầu tiên cần chạy sau khi tạo mới hoặc clone Terraform project.

**Hỏi: Vì sao không nên commit `terraform.tfstate`?**

Vì state chứa mapping giữa resource trong code và resource thật, đồng thời có thể chứa dữ liệu nhạy cảm. Nên dùng remote backend có mã hóa, locking và access control, còn state local không nên đưa vào Git.

**Hỏi: Khi resource đã tồn tại trên AWS nhưng chưa nằm trong Terraform thì làm gì?**

Viết resource block tương ứng trong `.tf`, sau đó dùng `terraform import ADDRESS ID` để đưa resource đó vào state. Sau import cần chạy `terraform plan` để chỉnh code cho khớp với resource thật.

## 37. Tóm tắt cực ngắn

Terraform CLI là công cụ `terraform` dùng để vận hành IaC lifecycle:

```
terraform init# chuẩn bị project
terraform fmt# format code
terraform validate# kiểm tra cấu hình
terraform plan# xem trước thay đổi
terraform apply# áp dụng thay đổi
terraform destroy# xóa hạ tầng
```

Các lệnh nâng cao cần nắm:

```
terraform state# quản lý state
terraform import# đưa resource có sẵn vào state
terraform output# xem output
terraform show# xem state/plan
terraform workspace# quản lý workspace
terraform providers# xem/quản lý provider
terraform test# test module/root module
```

Cách nhớ tốt nhất: **init → validate → plan → apply**, còn khi có sự cố thì nghĩ đến **state, import, refresh-only, force-unlock, workspace**.
