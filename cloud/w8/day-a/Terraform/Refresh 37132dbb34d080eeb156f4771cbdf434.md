# Refresh

`refresh` trong Terraform là quá trình **đọc lại trạng thái thật của resource trên cloud/provider** rồi cập nhật lại **Terraform state** để state phản ánh đúng thực tế.

Ví dụ: Terraform đang quản lý một EC2 instance. Ai đó vào AWS Console đổi tag, đổi security group, hoặc xóa resource. Khi đó state của Terraform có thể bị lệch so với thực tế. `refresh` giúp Terraform kiểm tra lại thực tế đó.

## Refresh làm gì?

Terraform refresh sẽ:

```
Real infrastructure trên AWS/Azure/GCP
        ↓ đọc lại
Terraform state file
```

Nó **không sửa hạ tầng thật**. Nó chỉ cập nhật state theo những gì provider trả về. Theo tài liệu HashiCorp, `terraform refresh` đọc cấu hình hiện tại của các remote objects và cập nhật Terraform state cho khớp; command này không chỉnh sửa remote objects thật, nhưng có chỉnh sửa state.

Ví dụ:

```
resource "aws_instance" "web" {
  ami           = "ami-xxx"
  instance_type = "t3.micro"

  tags = {
    Name = "web-server"
  }
}
```

Nếu bạn vào AWS Console đổi tag thành:

```
Name = web-server-manual
```

Khi chạy `terraform plan`, Terraform sẽ refresh trước, phát hiện resource thật đã bị đổi, rồi so sánh với file `.tf`.

## Refresh xảy ra khi nào?

Thông thường, bạn **không cần tự chạy refresh**.

Các lệnh sau đã tự refresh ngầm định:

```
terraform plan
terraform apply
```

HashiCorp nói rằng `plan` và `apply` mặc định chạy một bước **implicit in-memory refresh** để đối chiếu state với hạ tầng thật trước khi tạo execution plan.

Nói đơn giản:

```
terraform plan
```

thực chất sẽ làm gần như:

```
1. Đọc state hiện tại
2. Refresh state từ cloud/provider
3. So sánh với file .tf
4. Tạo plan: add/change/destroy
```

## `terraform refresh` có còn nên dùng không?

Không nên dùng nữa trong Terraform hiện đại.

Lệnh cũ:

```
terraform refresh
```

đã bị **deprecated**. HashiCorp khuyến nghị dùng `terraform plan -refresh-only` và `terraform apply -refresh-only` thay thế.

Lý do: `terraform refresh` có thể cập nhật state trực tiếp mà không cho bạn review kỹ trước. Nếu provider credentials sai, region sai, hoặc Terraform không đọc được resource, nó có thể hiểu nhầm resource đã bị xóa và cập nhật state sai. HashiCorp cảnh báo việc tự động apply refresh là rủi ro vì có thể khiến Terraform xóa tracking của resource khỏi state mà không có prompt xác nhận.

## Cách dùng hiện đại

### Xem trước state sẽ thay đổi gì

```
terraform plan -refresh-only
```

Lệnh này chỉ kiểm tra:

```
Nếu cập nhật state theo thực tế hiện tại thì state sẽ đổi như thế nào?
```

Nó **chưa ghi thay đổi vào state**.

### Chấp nhận cập nhật state

```
terraform apply-refresh-only
```

Lệnh này sẽ cập nhật Terraform state để khớp với hạ tầng thật, nhưng **không thay đổi resource thật**. HashiCorp khuyến nghị cách này vì bạn có thể review trước các thay đổi state trước khi apply.

## Phân biệt `plan`, `refresh-only`, và `apply`

| Lệnh | Mục đích | Có đổi hạ tầng thật không? | Có đổi state không? |
| --- | --- | --- | --- |
| `terraform plan` | Xem Terraform sẽ làm gì để hạ tầng khớp với code | Không | Không ghi trực tiếp |
| `terraform apply` | Thực thi thay đổi hạ tầng theo code | Có | Có |
| `terraform plan -refresh-only` | Xem state sẽ đổi gì để khớp thực tế | Không | Không |
| `terraform apply -refresh-only` | Cập nhật state theo thực tế | Không | Có |
| `terraform refresh` | Cách cũ để cập nhật state | Không | Có, nhưng deprecated |

## Ví dụ dễ hiểu

Giả sử file Terraform khai báo:

```
tags = {
  Name = "web-server"
}
```

Nhưng trên AWS Console, ai đó sửa thành:

```
Name = web-server-manual
```

Khi chạy:

```
terraform plan
```

Terraform có thể báo:

```
Objects have changed outside of Terraform
```

Sau đó nó sẽ đề xuất đưa resource quay lại trạng thái trong code:

```
Name: "web-server-manual" => "web-server"
```

Nhưng nếu chạy:

```
terraform plan-refresh-only
```

Terraform sẽ không đề xuất sửa AWS resource. Nó chỉ nói rằng state có thể được cập nhật để ghi nhận thực tế hiện tại.

## Khi nào nên dùng refresh-only?

Nên dùng khi bạn muốn kiểm tra hoặc đồng bộ state sau khi có thay đổi ngoài Terraform, ví dụ:

```
- Ai đó sửa resource bằng AWS Console
- Resource bị xóa thủ công
- Provider cập nhật thêm computed attribute
- Muốn kiểm tra drift giữa state và real infrastructure
- Muốn cập nhật output trong state mà không đổi hạ tầng
```

## Ghi nhớ ngắn gọn

`refresh` = **đồng bộ Terraform state với hạ tầng thật**.

Trong Terraform hiện đại, nên dùng:

```
terraform plan-refresh-only
```

để xem trước, rồi nếu hợp lý thì:

```
terraform apply-refresh-only
```

Không nên dùng:

```
terraform refresh
```

vì nó đã deprecated và rủi ro hơn.
