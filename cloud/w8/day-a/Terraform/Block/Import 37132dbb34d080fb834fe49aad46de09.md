# Import

`import` trong Terraform dùng để **đưa resource đã tồn tại sẵn ngoài thực tế vào Terraform state**, để Terraform bắt đầu quản lý resource đó bằng IaC. Ví dụ: bạn đã tạo EC2, S3 bucket, VPC, Route 53 Hosted Zone bằng AWS Console, bây giờ muốn Terraform quản lý chúng thì dùng `import`. Terraform không tạo resource mới khi import; nó chỉ ánh xạ resource thật vào **Terraform state**.

## Khi nào cần dùng `import`?

Dùng `import` khi:

1. Resource đã được tạo thủ công bằng AWS Console.
2. Resource được tạo bởi tool khác như CloudFormation, CDK, script, hoặc người khác.
3. Bạn muốn chuyển hạ tầng hiện có sang Terraform.
4. Terraform state bị mất nhưng resource thật vẫn còn.
5. Bạn muốn bắt đầu quản lý một resource cũ bằng Terraform.

Ví dụ thực tế:

```
Bạn đã có một S3 bucket tên my-existing-bucket.
Bucket này chưa nằm trong Terraform state.
Bạn muốn Terraform quản lý nó.
=> Dùng import.
```

## Có 2 cách import chính

Hiện nay nên hiểu `import` theo 2 cách:

### Dùng `terraform import` CLI

Cú pháp:

```
terraform import ADDRESS ID
```

Trong đó:

```
ADDRESS = địa chỉ resource trong Terraform config
ID      = ID thật của resource trên cloud/provider
```

Terraform CLI sẽ tìm resource thật theo `ID`, rồi import nó vào Terraform state tại `ADDRESS`. Lệnh này có thể import resource ở root module hoặc trong child module.

Ví dụ import S3 bucket:

```
resource "aws_s3_bucket" "main" {
  bucket = "my-existing-bucket"
}
```

Sau đó chạy:

```
terraform import aws_s3_bucket.main my-existing-bucket
```

Ý nghĩa:

```
aws_s3_bucket.main     = địa chỉ Terraform muốn quản lý
my-existing-bucket     = bucket thật đang tồn tại trên AWS
```

Sau khi import, Terraform state sẽ biết rằng:

```
aws_s3_bucket.main tương ứng với S3 bucket my-existing-bucket
```

### Dùng `import` block trong `.tf` file

Đây là cách mới hơn, rõ ràng hơn, dễ review trong Git hơn.

Ví dụ:

```
import {
  to = aws_s3_bucket.main
  id = "my-existing-bucket"
}

resource "aws_s3_bucket" "main" {
  bucket = "my-existing-bucket"
}
```

Trong đó:

```
to = aws_s3_bucket.main
```

là địa chỉ resource trong Terraform.

```
id = "my-existing-bucket"
```

là ID thật của resource bên ngoài.

Theo tài liệu Terraform, `import` block cần khai báo địa chỉ resource đích bằng `to`, và ID resource thật bằng `id`. Resource đích cũng cần có `resource` block tương ứng trong configuration.

Sau đó chạy:

```
terraform plan
terraform apply
```

Terraform sẽ import resource vào state khi apply.

## Luồng import chuẩn

Quy trình nên làm như sau:

```
Bước 1: Xác định resource thật đang tồn tại
Bước 2: Viết resource block tương ứng trong Terraform
Bước 3: Viết import block hoặc chạy terraform import
Bước 4: Chạy terraform plan
Bước 5: Kiểm tra xem Terraform có muốn thay đổi/xóa resource không
Bước 6: Chạy terraform apply nếu plan an toàn
```

Terraform khuyến nghị khi import resource riêng lẻ thì nên định nghĩa resource đích, thêm `import` block, chạy `terraform plan`, kiểm tra plan, rồi `terraform apply`.

## Ví dụ import EC2 instance

Giả sử bạn có EC2 instance thật với ID:

```
i-0123456789abcdef0
```

Bạn viết Terraform config:

```
resource "aws_instance" "web" {
  ami           = "ami-xxxxxxxx"
  instance_type = "t3.micro"

  tags = {
    Name = "web-server"
  }
}
```

Thêm import block:

```
import {
  to = aws_instance.web
  id = "i-0123456789abcdef0"
}
```

Sau đó chạy:

```
terraform plan
terraform apply
```

Terraform sẽ đưa EC2 instance đó vào state.

## Điểm rất quan trọng

`import` **không tự động viết đầy đủ configuration cho bạn** trong cách truyền thống. Nó chủ yếu đưa resource vào state. Nếu file `.tf` của bạn thiếu hoặc khác cấu hình thật, lần `terraform plan` tiếp theo có thể báo Terraform muốn sửa resource.

Ví dụ, resource thật đang là:

```
instance_type = t3.small
```

Nhưng bạn viết trong Terraform:

```
instance_type = "t3.micro"
```

Sau khi import, chạy `terraform plan`, Terraform có thể muốn đổi EC2 từ `t3.small` sang `t3.micro`.

Vì vậy sau khi import cần chạy:

```
terraform plan
```

để kiểm tra Terraform có định thay đổi gì không.

## Terraform có thể generate config không?

Có. Với import block, Terraform hỗ trợ workflow tạo configuration bằng cờ `-generate-config-out`. Bạn có thể viết import block trước, rồi dùng `terraform plan -generate-config-out=...` để Terraform sinh resource block tương ứng.

Ví dụ:

```
import {
  to = aws_s3_bucket.main
  id = "my-existing-bucket"
}
```

Chạy:

```
terraform plan-generate-config-out=generated.tf
```

Terraform sẽ cố gắng sinh file cấu hình cho resource được import.

## So sánh nhanh

| Cách | Đặc điểm | Khi nên dùng |
| --- | --- | --- |
| `terraform import ADDRESS ID` | Lệnh CLI, import trực tiếp vào state | Nhanh, dùng một lần, lab/test |
| `import {}` block | Viết trong code `.tf`, review được bằng Git | Nên dùng trong project nghiêm túc |
| `-generate-config-out` | Terraform sinh config từ resource thật | Hữu ích khi chưa biết viết resource block đầy đủ |

## Lưu ý về `ID`

Mỗi resource có cách định danh khác nhau. Ví dụ:

```
S3 bucket       -> bucket name
EC2 instance    -> instance ID
VPC             -> vpc ID
Subnet          -> subnet ID
IAM role        -> role name
Route 53 zone   -> hosted zone ID hoặc thông tin theo provider
```

Terraform nói rằng giá trị `id` phụ thuộc vào loại resource đang import, và bạn cần xem tài liệu của provider/resource tương ứng để biết ID chính xác.

## Tóm lại

`import` trong Terraform là cơ chế dùng để **đưa resource đã tồn tại vào Terraform state**, giúp Terraform bắt đầu quản lý resource đó.

Cần nhớ 3 ý chính:

```
import không tạo resource mới
import chỉ đưa resource thật vào state
sau import phải kiểm tra terraform plan thật kỹ
```

Cách hiện đại, dễ quản lý hơn là dùng:

```
import {
  to = aws_s3_bucket.main
  id = "my-existing-bucket"
}
```

kết hợp với:

```
terraform plan
terraform apply
```
