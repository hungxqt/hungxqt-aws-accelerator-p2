# Moved

Trong Terraform, **`moved` block** dùng để khai báo rằng một resource hoặc module đã được **đổi địa chỉ trong code**, nhưng thực tế hạ tầng bên ngoài **không thay đổi**.

Nói đơn giản:

> `moved` giúp Terraform hiểu rằng “resource này chỉ được đổi tên hoặc chuyển chỗ”, không phải resource mới cần tạo lại.
> 

Theo tài liệu Terraform, nếu bạn đổi tên resource mà không khai báo `moved`, Terraform có thể hiểu là cần **destroy resource cũ** và **create resource mới**. `moved` giúp cập nhật địa chỉ resource trong state mà không phá hủy resource thật.

## Cú pháp

```
moved {
  from = aws_instance.old
  to   = aws_instance.new
}
```

Trong đó:

- from: là địa chỉ cũ của resource/module.
- to: là địa chỉ mới của resource/module.

## Ví dụ đổi tên resource

Ban đầu bạn có:

```
resource "aws_s3_bucket" "old_name" {
  bucket = "my-app-bucket"
}
```

Sau đó bạn muốn đổi tên resource trong code cho rõ nghĩa hơn:

```
resource "aws_s3_bucket" "app_bucket" {
  bucket = "my-app-bucket"
}
```

Nếu chỉ đổi như vậy, Terraform có thể hiểu:

```
destroy aws_s3_bucket.old_name
create aws_s3_bucket.app_bucket
```

Để tránh điều đó, bạn thêm:

```
moved {
  from = aws_s3_bucket.old_name
  to   = aws_s3_bucket.app_bucket
}
```

Khi chạy:

```
terraform plan
```

Terraform sẽ hiểu rằng resource đã được **move trong state**, không phải xóa rồi tạo lại.

## Dùng khi nào?

`moved` thường dùng trong các trường hợp:

1. Đổi tên resource:

```
from = aws_instance.web
to   = aws_instance.app_server
```

1. Chuyển resource vào module:

```
from = aws_vpc.main
to   = module.network.aws_vpc.main
```

1. Đổi tên module:

```
from = module.app
to   = module.frontend
```

1. Chuyển từ resource đơn lẻ sang `count` hoặc `for_each`.

Ví dụ:

```
moved {
  from = aws_instance.web
  to   = aws_instance.web["main"]
}
```

## So sánh với `terraform state mv`

Trước đây, người ta hay dùng:

```
terraform statemv aws_instance.old aws_instance.new
```

Nhưng cách này là thao tác thủ công trực tiếp với state.

Còn `moved` tốt hơn trong nhiều trường hợp vì nó được viết trực tiếp trong Terraform code, dễ review qua Git, phù hợp CI/CD và giúp cả team hiểu lịch sử refactor.

## Ghi nhớ ngắn gọn

```
moved
```

không tạo resource mới, không xóa resource cũ. Nó chỉ nói với Terraform rằng:

> “Địa chỉ resource trong code đã thay đổi, hãy cập nhật state theo địa chỉ mới.”
> 

Nên dùng `moved` khi bạn **refactor Terraform code**: đổi tên resource, chuyển resource vào module, đổi cấu trúc module, hoặc chuyển sang `for_each/count`.
